# Stage D Portfolio Workspace

<!--
作用：约束组合研究代理只能从 20 只深研候选、已有持仓与挂单形成战略权重方案。
重要性：这是 Codex 工作区内的最高优先级安全边界，禁止最终数量、实际订单和 Alpaca 操作。
-->

- 只执行第二阶段 `portfolio_decision`。
- 读取 `data/portfolio_input.json`、其拆分副本和 `config/` 中的策略、风险约束。
- `previous_portfolio` 可能来自上一交易日；用它保持策略、复核条件和分批意图连续，
  但当前持仓、资金、订单、价格和有效期必须以本轮输入为准。重大变化需明确解释。
- `market_assessment.summary` 必须使用中文；Schema 枚举、股票代码、来源 ID 和 URL
  保持原样。
- 新开仓只能来自当前 coarse 候选且 `screen_new_position_eligible=true`。
- coarse 之外的已有持仓只能 `hold`、`reduce` 或 `close`。
- initial guidance 是研究偏好，不是强制交易命令；可以接受、修改或拒绝。
- 现金比例可以是 0–100%；允许全空仓、接近满仓、平衡或集中，最终状态由模型基于
  长期资本竞争决定，不得用固定仓位偏好替代机会比较。
- 对现有持仓、按 coarse `rank` 排序并排除现有证券持仓后的前三个候选和现金使用
  同一套资本竞争维度；不得以主观选择的较低排名候选替换这三个必需比较项，其他替代项
  可以追加。`CASH` 比较项必须写 `comparator_type="cash"` 且
  `current_position=false`；该布尔值只表示是否为现有证券持仓，不表示账户是否有现金。
  持仓身份只允许形成有明确成本与证据的换手缓冲，不能提高质量、估值或预期回报判断。
- 每个现有持仓必须给出“不持有时是否仍会买入”的反事实和最佳替代标的；
  `increase` 必须对应 `would_buy_if_not_held=true`。
- 用户只会不定期投入不确定金额，不存在每月固定金额或频率；不得安排固定月供、
  机械定投或提前计入未来资金。
- 检测到既有 USDT 或等价券商 Crypto 余额时，先规划兑换为 USD；只有券商对账
  确认卖出且 USD 购买力刷新后，才能把这部分资金用于股票或 ETF。
- 每个持仓必须区分市场价格、价值区间、估值证据、预期回报场景和永久损失风险。
  估值区间至少绑定两个可复算输入及来源；不要把范围较宽自动降级为证据不足。
- `no_reliable_estimate` 只能在至少两种适用估值方法均因明确缺失事实失败后使用；此时
  `valuation.evidence_quality` 必须严格写 `insufficient`，估值数字为 null，并填写
  `no_estimate_reason`。开仓或加仓的估值证据质量和预期回报置信度都不得低于 medium。
- 不会从零重新买入的持仓必须量化换仓成本、列出未解决证据、在30天内复核，并承诺
  证据到期仍缺失时减仓或退出；持仓身份本身不能无限延长等待。
- 现金可以是0%；目标现金达到25%时必须给出至少两个可衡量部署触发器并在14天内复核。
- 每个决策必须给出最多30天的复核日和至少两个可衡量监控触发器。
- 对所有持有或拟配置的 ETF 给出穿透式重叠与集中度研究；数据不足时明确
  partial/unavailable，禁止编造权重。
- `latest_quote` 只是带时间戳的战略估值参考，不是实时行情；不得把它描述成
  live quote，实际执行前必须重新取价验证。
- 允许中等回撤、集中、高风险或抄底；更大回撤容忍度需要更强的长期回报与生存
  证据。价格下跌本身不构成价值证据，稀释和 thesis 破裂必须优先检查。
- 每项决策给出非订单化的分批建仓计划，并允许 wait 或 no-add。
- `external_discoveries` 只能进入 watchlist，未经后续 Python 验证不得进入 decisions。
- 不输出最终数量、notional、订单类型、TIF、订单 ID、提交或成交字段。
- 不创建、取消、替换或提交实际订单，不调用 Alpaca。
- 只允许把临时输出写入 `.tmp/codex/`。
- 最终响应只能是符合 Schema 的一个 JSON 对象，不得附加 Markdown。
